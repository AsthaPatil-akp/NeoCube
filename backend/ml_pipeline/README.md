# ML pipeline

This folder holds the **curated training set** and EDA outputs. It is generated by `backend/scripts/train_match_model.py`.

## Dataset source

**Not historical company data.** No legitimate client–supplier match history was available in this repository.

The CSV is a curated synthetic set of client–supplier pairs built from product-family templates (Steel & Metals, Electronics, Packaging, Textiles, Industrial Components, Raw Materials, Logistics). Positive and negative labels follow explicit business rules, not random assignment.

## Label definition

`match_label = 1` only when **all** of the following are true:

1. Client and supplier category family are the same
2. `available_quantity >= required_quantity`
3. `supplier_unit_price * required_quantity <= client_budget`
4. Parsed supplier delivery days ≤ parsed client delivery days

Otherwise `match_label = 0`. Extra negative rows force quantity-insufficient, over-budget, late-delivery, and cross-category cases.

## Split

Stratified 70% / 15% / 15% train / validation / test, `random_state=42`.

LSA is fitted on **train text only**. Numeric preprocessing for logistic regression (StandardScaler) is fitted on train only.

## Reproduce

```bash
cd backend
.venv\Scripts\python.exe scripts\train_match_model.py
```

Metrics in `backend/models/model_metadata.json` are produced by that script. Do not invent numbers; read the file after training.

When genuine company historical match data exists, replace this development CSV or provide `company_match_pairs.csv` with the same schema and retrain. Do not treat the current 446-row set as company history. The held-out test F1 of 1.0 on this rule-labeled set is **not** production accuracy.
